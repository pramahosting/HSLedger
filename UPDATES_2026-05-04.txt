UPDATE 1 — Purchase Entry Table: Fix "Type Twice" Bug (Draft Form Workflow)
────────────────────────────────────────────────────────────────────────────────

FILE CHANGED:
  streamlit_frontend/frontend/components/shares_trading_taxation_ui.py

PROBLEM:
  The Missing Buys tab used Streamlit's st.data_editor for entering purchase
  lots. Because st.data_editor triggers a full page rerun on every keystroke,
  the state would race and values would visually disappear on first entry.
  Users had to type each field twice to get values to stick.

SOLUTION:
  Replaced the data_editor entry pattern with a two-part layout:

  1. READ-ONLY TABLE (st.dataframe)
     - Shows all previously confirmed purchase rows.
     - No editing in this table — it is display only.

  2. DRAFT ENTRY FORM (st.form)
     - Five input fields: Purchase Date, Qty, Unit Price, Brokerage, GST.
     - All keystrokes stay inside the form's local state and do NOT trigger
       Streamlit reruns. The page is stable while typing.
     - A single "Add Data" button (st.form_submit_button) triggers submission.

  3. VALIDATION ON SUBMIT ONLY
     - Purchase Date: required, must match dd/mm/yyyy.
     - Qty: must be > 0.
     - Unit Price: must be > 0.
     - Brokerage: can be 0, cannot be negative.
     - GST: can be 0, cannot be negative.
     - Field-level error messages appear below the form on failure.

  4. FORM RESET BEHAVIOUR
     - On SUCCESS: a per-ticker counter increments, changing the form's key,
       which forces a fresh empty form on the next render. No stale values.
     - On FAILURE: the counter does NOT increment, so the form re-renders
       with the user's typed values intact. Only the bad field needs fixing.

  5. FIFO CALCULATIONS
     - The FIFO engine only runs on confirmed (saved) rows.
     - Draft state (in-progress typing) is never fed into the engine.
     - Preview updates only after "Add Data" is successfully clicked.

TECHNICAL DETAIL:
  A per-ticker session state counter (stt_draft_ctr_{ticker}) acts as a
  form key suffix. Incrementing it on success causes React/Streamlit to
  unmount and remount the form, which clears inputs without relying on
  clear_on_submit (which would also clear inputs on validation failure,
  forcing the user to retype corrected values).

STATE ADDED:
  stt_draft_err_{ticker}  — stores field-level error dict per ticker
  stt_draft_ctr_{ticker}  — integer counter used as form key suffix

UPDATE 2 — Cassandra Investigation & POC Test
────────────────────────────────────────────────────────────────────────────────

FILES CREATED:
  streamlit_frontend/tests/cassandra_trading_poc_test.py

INVESTIGATION FINDINGS:

  The codebase contained references to Cassandra in two files:
    streamlit_frontend/backend/db/cassandra_client.py
    streamlit_frontend/backend/db/USER.py

  After inspection, Cassandra was found to be INACTIVE and NON-FUNCTIONAL:

  - cassandra_client.py is a 5-line stub with a module-level
    print(cluster.connect('hsledger')) call that crashes on import.
  - USER.py imports get_cnxn from cassandra_client, but get_cnxn is
    never defined anywhere — raises ImportError on load.
  - The cassandra-driver package is NOT listed in requirements.txt.
    Any import of cassandra.* raises ModuleNotFoundError at runtime.
  - No CREATE KEYSPACE or CREATE TABLE CQL statements exist anywhere
    in the codebase.
  - No production data is stored in Cassandra. The real active database
    is SQLite (reconciliation.db) via SQLAlchemy.

CASSANDRA POC TEST FILE:
  streamlit_frontend/tests/cassandra_trading_poc_test.py

  A self-contained proof-of-concept that, given a running Cassandra
  instance, proves user-level data isolation works at the partition
  key level. It:
    - Creates a hsledger_test keyspace (never touches production).
    - Creates three tables: manual_purchase_lots_by_user_fy,
      tax_reports_by_user_fy, uploaded_trading_files_by_user_fy.
    - Seeds data for user_a (3 lots, 1 report) and user_b (2 lots, 1 report).
    - Runs 9 isolation assertions proving cross-user access returns
      zero rows at the data model level (structural guarantee from the
      Cassandra partition key, not application-level filtering).
    - Drops the test keyspace on completion.

  NOTE: Requires  pip install cassandra-driver  and a running Cassandra
  instance (e.g. Docker: docker run -d -p 9042:9042 cassandra:4.1).
  This file is a POC only and is NOT part of the production codebase.

DECISION:
  The production persistence implementation (Update 3 below) uses the
  existing SQLite/SQLAlchemy stack, consistent with the rest of the app.

UPDATE 3 — Full Persistent Storage for Shares Trading Taxation (Per-User)
────────────────────────────────────────────────────────────────────────────────

PROBLEM BEFORE THIS UPDATE:
  - All purchase lots typed into Missing Buys were stored only in
    Streamlit session_state — lost on page refresh or logout.
  - Generated tax reports were never saved anywhere.
  - There was no session token system. user_id was passed directly in
    the HTTP request body, which is a security flaw (any user could
    claim any user_id).
  - No mechanism existed to load a user's previous work on re-login.

3A — New Database Models (SQLite via SQLAlchemy)
────────────────────────────────────────────────────────────────────────────────

FILE: app/models/session_token.py  (NEW)

  Table: sessions
  Columns:
    token       TEXT  PRIMARY KEY  (UUID string)
    user_id     INT   NOT NULL, indexed
    created_at  DATETIME
    expires_at  DATETIME  (default: 7 days from creation)

  Purpose: Maps a UUID token to a user_id. Issued on login.
  Used by: get_current_user() dependency to resolve identity.

FILE: app/models/manual_purchase_lot.py  (NEW)

  Table: manual_purchase_lots
  Columns:
    id             INT   PRIMARY KEY AUTOINCREMENT
    user_id        INT   NOT NULL, indexed
    financial_year TEXT  (e.g. "2024-25")
    ticker         TEXT  (e.g. "CBA")
    purchase_date  TEXT  (dd/mm/yyyy — matches UI input format)
    qty            FLOAT
    unit_price     FLOAT
    brokerage      FLOAT  default 0.0
    gst            FLOAT  default 0.0
    created_at     DATETIME

  Purpose: Persists manually entered purchase lots per user + FY.
  User isolation: every query filters WHERE user_id = current_user.id.

FILE: app/models/tax_report.py  (NEW)

  Table: tax_reports
  Columns:
    id                   INT   PRIMARY KEY AUTOINCREMENT
    user_id              INT   NOT NULL, indexed
    financial_year       TEXT
    net_taxable_gain     FLOAT
    gross_capital_gains  FLOAT
    gross_capital_losses FLOAT
    cgt_discount_applied FLOAT
    report_json          TEXT  (full serialised report, nullable)
    created_at           DATETIME

  Purpose: Saves a summary record every time a final tax report is
  generated. Listed in the Past Reports section of the UI.

3B — Authentication: Session Token on Login
────────────────────────────────────────────────────────────────────────────────

FILE: app/api/auth.py  (MODIFIED)

  BEFORE: /auth/login returned UserResponse{id, email, roles, ...}
          No token was issued. user_id was sent in API request bodies
          by the frontend (insecure).

  AFTER:  /auth/login returns LoginResponse{token, user}
          - token: UUID string stored in the sessions table.
          - user: the existing UserResponse fields unchanged.
          - Session expires after 7 days.

  New helper function _create_session_token(user, db) encapsulates
  UUID generation, SessionToken row creation, and commit.

  authenticate_user() now returns the User ORM object (previously
  returned UserResponse), allowing the endpoint handler to access
  user.id for session creation before building the response.

FILE: app/api/deps.py  (NEW)

  Provides a single FastAPI dependency used by all protected routes:

    def get_current_user(
        x_auth_token: str = Header(..., alias="X-Auth-Token"),
        db: Session = Depends(get_db),
    ) -> User:

  Steps:
    1. Reads the X-Auth-Token request header.
    2. Looks up the token in the sessions table.
    3. Checks expiry (raises 401 if expired, deletes the stale row).
    4. Returns the User ORM object.

  SECURITY GUARANTEE:
    user_id is NEVER read from the request body, path, or query string
    on any trading route. It is always derived from this dependency.

3C — New API Routes (/trading)
────────────────────────────────────────────────────────────────────────────────

FILE: app/api/trading.py  (NEW)
REGISTERED IN: app/main.py  (prefix="/trading", tags=["trading"])

  All routes require a valid X-Auth-Token header. user_id on every
  database query comes only from current_user (Depends(get_current_user)).

  PURCHASE LOT ROUTES:

    POST   /trading/lots
      Body: {financial_year, ticker, purchase_date, qty, unit_price,
             brokerage, gst}
      Saves one lot for the authenticated user. Returns saved lot with id.

    GET    /trading/lots?financial_year=...&ticker=...
      Returns all lots for the current user + FY, ordered by ticker then
      purchase_date. Optional ticker filter.

    DELETE /trading/lots/{lot_id}
      Deletes the lot only if BOTH lot_id AND user_id match.
      A valid token for user A cannot delete user B's lot even with a
      correct lot_id — ownership is enforced at the query level.

  TAX REPORT ROUTES:

    POST   /trading/reports
      Body: {financial_year, net_taxable_gain, gross_capital_gains,
             gross_capital_losses, cgt_discount_applied, report_json}
      Saves a report summary for the authenticated user.

    GET    /trading/reports?financial_year=...
      Returns all saved reports for the current user + FY, newest first
      (ORDER BY created_at DESC).

3D — Frontend: Token Storage and Trading API Client
────────────────────────────────────────────────────────────────────────────────

FILE: streamlit_frontend/auth/auth_json_module.py  (MODIFIED)

  The login handler now reads the nested LoginResponse:
    auth_token = result["token"]
    user_data  = result["user"]
  and stores both in session state:
    st.session_state.auth_token = auth_token
    st.session_state.user       = user_data

  Graceful fallback: if the response is the old flat format (during
  transition), user.get("user", user) falls back to the top-level dict
  so existing fields (roles, is_admin, etc.) continue to work.

FILE: streamlit_frontend/auth/api_client.py  (MODIFIED)

  Added helper _auth_headers(token) that returns {"X-Auth-Token": token}.
  user_id is never sent in any request body in these new functions.

  New functions added:

    save_purchase_lot(token, financial_year, ticker, purchase_date,
                      qty, unit_price, brokerage, gst)
      POST /trading/lots — returns saved lot dict or None.

    load_purchase_lots(token, financial_year, ticker=None)
      GET /trading/lots — returns list of lot dicts or [].

    delete_purchase_lot(token, lot_id)
      DELETE /trading/lots/{lot_id} — returns True on success.

    save_tax_report(token, financial_year, net_taxable_gain,
                    gross_capital_gains, gross_capital_losses,
                    cgt_discount_applied, report_json=None)
      POST /trading/reports — returns saved report dict or None.

    list_tax_reports(token, financial_year)
      GET /trading/reports — returns list of report dicts or [].

  All new functions catch exceptions silently and return None / []
  so the UI degrades gracefully when the backend is unavailable.

3E — UI: Load, Save, and Display Persistent Data
────────────────────────────────────────────────────────────────────────────────

FILE: streamlit_frontend/frontend/components/shares_trading_taxation_ui.py
      (MODIFIED — additions to the file changed in Update 1)

NEW HELPER FUNCTIONS ADDED:

  _auth_token()
    Returns st.session_state.auth_token or None.
    Central check — all API helpers call this first.

  _load_lots_from_api(fy)
    Calls load_purchase_lots() and merges returned rows into
    stt_buy_records, grouped by ticker into DataFrames matching
    the _empty_buy_df() schema. Called once per process-files run.
    Silent on failure (backend unavailable).

  _save_lot_to_api(ticker, fy, row)
    Calls save_purchase_lot() after a lot is confirmed via "Add Data".
    Uses stt_stored_fy as the financial year.
    Silent on failure.

  _save_report_to_api(result, fy)
    Aggregates fy_summaries from the pipeline result and calls
    save_tax_report() after "Generate Final Tax Report" completes.
    Silent on failure.

  _render_past_reports(fy)
    Calls list_tax_reports() and renders results in an st.expander
    "Past Reports — FY {fy} ({n} saved)".
    Shows: Generated date, Net Taxable Gain, Gross Gains, Gross Losses,
    CGT Discount per report row, newest first.
    Only rendered when auth_token is present in session state.

WIRED INTO render() FUNCTION:

  1. LOAD ON PROCESS FILES
     After ▶ Process Files completes, stt_lots_loaded is set False.
     On the next render with a result present, _load_lots_from_api(fy)
     runs once and stt_lots_loaded is set True. Previously saved lots
     for this FY automatically populate the Missing Buys tables.

  2. SAVE ON "ADD DATA"
     After the draft form validates and appends a row to stt_buy_records,
     _save_lot_to_api() is called with the same row data.

  3. SAVE REPORT ON GENERATION
     After _run_final_pipeline() completes successfully,
     _save_report_to_api() is called with the result and stored FY.

  4. PAST REPORTS SECTION
     _render_past_reports() is called before the "no result yet" early
     return, so users can see their report history even before uploading
     files in the current session.

  5. RESET CLEARS LOAD FLAG
     The ↺ Reset button sets stt_lots_loaded to False so that after a
     fresh process run the lots are reloaded cleanly.

STATE ADDED TO _init():
  stt_lots_loaded  (bool, default False)

SECURITY PROPERTIES ENFORCED
────────────────────────────────────────────────────────────────────────────────

  1. user_id is NEVER accepted from the frontend request body.
     It is derived exclusively from the X-Auth-Token header via
     get_current_user() on every protected route.

  2. Every database query on manual_purchase_lots and tax_reports
     includes  WHERE user_id = current_user.id  — there is no
     code path that returns another user's rows.

  3. The DELETE /trading/lots/{lot_id} route filters by BOTH
     lot_id AND user_id. Knowing a lot's integer ID is not enough
     to delete it — the token must also belong to the lot's owner.

  4. Session tokens expire after 7 days. Expired tokens are deleted
     from the sessions table on first use after expiry.

  5. Passwords remain bcrypt-hashed (unchanged from original system).
